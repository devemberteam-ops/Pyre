## SYNC ENGINE (sync_engine.dart, sync_manifest.dart, app_store LWW/tombstone)
- **S-BUG1 (HIGH, lost update) — "Keep this device" conflict is reverted next tick.** On a keep-local resolution (preferThisDevice or "Keep this device" in Ask), the apply path skips the incoming record but does NOT bump the local record's mtime (sync_engine.dart ~529-535; sync_conflict.dart:140-141). Watermark then advances (~1174), so next tick `_collectDirty` won't push the local winner (its mtime < serverTime), and the next pull LWW-overwrites the local "winner" with the peer's copy. The conflict feature does the OPPOSITE of the user's choice for both keep-local outcomes. FIX: on keep-local, bump local mtime to serverTime+1/now so it out-dates the peer + gets pushed.
- **S-BUG2 (HIGH, missing data) — watermark TOCTOU drops records written during a pull.** Server stamps `serverTime = DateTime.now()` AFTER selecting `mtime > since` (pyre_server.dart ~452). A write landing between the selection and the now()-stamp gets mtime < serverTime but isn't in the response; client adopts serverTime as watermark (~1174) → next pull excludes it forever. Reachable because the desktop AppStore is mutated by the same process serving /pull, which awaits during serialization. FIX: capture serverTime BEFORE the selection snapshot (or use max-included mtime).
- **S-BUG3 (MEDIUM) — tombstone reap boundary asymmetry.** Reap uses `mtime < tombstoneMtime` (sync_engine ~909-916; pyre_server ~1466-1469) but suppression `isTombstonedNewer` uses `>=` (app_store ~1140-1143). At equality the record stays live AND tombstoned → divergence. Equality is MANUFACTURED by the server clamping both a record push and its tombstone to the same serverNow. FIX: make reap `<=` to match suppression.
- **S-BUG4 (MEDIUM, secret durability) — provider apply before tombstone apply.** applyProviders (writes the decrypted key to OS-secure storage) runs before applyTombstones (which SecureKeys.delete) in the same tick (sync_engine ~1039-1040). If the tick is killed between the key-write and the reap, a DELETED provider's plaintext key is left in secure storage with no live record. FIX: apply tombstones (+ SecureKeys.delete) before provider apply, or skip the key-write when a newer tombstone for that id is in the same payload.
- **S-FLAG5 (design call) — settings/botbooruProfile excluded from conflict detection.** Both-sides edits to settings or the botbooru profile silently LWW even in Ask/prefer mode (no dialog). Documented as deliberate; flagging because botbooruProfile is user-authored prose where silent loss is more visible. FOUNDER'S CALL.
- CORRECT (don't chase): per-record fromJson isolation; hard-reject watermark hold; fullResync in-flight wait; W7 attachment dedup; manifest digest.

## LAN SERVER / SECURITY (pyre_server.dart, rate_limit.dart)
- **N1 (MEDIUM, DoS) — /llm/stream reads an unbounded body.** `req.readAsString()` (pyre_server ~857) with no cap; a paired device sends a multi-GB body → OOM before validation. The sibling POSTs /push (128MB) + /attachments (64MB) were explicitly capped; this cost-bearing route was missed. The rate-limit gates request COUNT, not body SIZE. FIX: same declared-Content-Length 413 + mid-stream abort as /push.
- **N2 (LOW, DoS) — /pair (UNAUTHENTICATED) + /attachments/missing read unbounded bodies** (~240, ~774). /pair is the cheapest pre-auth DoS surface. FIX: small body cap (e.g. 64KB).
- VERIFIED SECURE (attacked hard, held): NO auth bypass (auth + shelf_router consume the same normalized+anchored path — probed //pull, /x/../pull, %2F, case, null — none public-to-auth-yet-routed-to-protected); NO /attachments path traversal (`[^/]+` + `/`/`..` reject + `.bin` suffix); NO proxy key leak (errors scrubbed via scrubProviderBody); rate-limit keyed on device.id, isolation sound; CORS same-origin-only; bearers 256-bit + SHA-256 stored + constant-time; pairing tokens single-use 5-min TTL.
- KNOWN/FLAGGED (still real, deferred trade-offs, FOUNDER'S CALL): /bbx unauth outbound-fetch (MEDIUM) + /bbx raw-error leak (LOW); binds 0.0.0.0 + plaintext HTTP (S2); plaintext keys-in-backup (S4); pairing token shown plaintext (S6) — all carry a user-facing "traffic not encrypted" warning.

## WEB CLIENT (main.dart web boot, streaming/web download, avatar/gallery web fetch, web pairing)
- **W-BUG1 (MEDIUM, nuanced) — web avatars/gallery/lightbox via NetworkImage(headers).** /attachments is bearer-gated; web resolves pyre:// → NetworkImage(url, headers:{Authorization}). On the CanvasKit/Skwasm renderer the header-fetch path works SAME-ORIGIN (the canonical "served by the paired desktop" case) but is fragile / breaks non-same-origin. Today's deployment is same-origin, so mostly OK now, but brittle. ASSESS — likely a robustness improvement, not an active break in the canonical setup.
- **W-BUG2 (MEDIUM, latent) — web client hardcodes http://.** lan_client.dart `baseUrl => 'http://...'` (and pair() builds http:// ) drive ALL web data paths (pull/push/llm-stream/attachments). A page served over HTTPS → browser blocks the http:// subresources (mixed content) → app dead. The web-pair screen even DETECTS https then ignores it (dead code). Latent (HTTP-only LAN works today). FIX: derive scheme from the page location / pairing URL. FOUNDER'S CALL whether HTTPS hosting matters yet.
- **W-BUG3 (LOW-MED, clean fix) — chat export degrades to clipboard on web.** chat_screen.dart ~2387 dumps the export to the clipboard on web instead of using `downloadBytesToBrowser` (the helper that card/persona/backup/gallery export ALL migrated to in 1.1.3). A missed migration. FIX: wire chat export through downloadBytesToBrowser on web.
- CORRECT (ruled out): SSE streaming on web (FetchClient) streams fine; web Blob/anchor download correct; CORS same-origin clean; secure_keys web no-op fine.
